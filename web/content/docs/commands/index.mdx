## Global flags

| Flag | Effect |
| --- | --- |
| `-s`, `--site` | Site URL exactly as in `sites list`, or a bare host (or `BWT_SITE`) |
| `--profile` | Saved profile (or `BWT_PROFILE`) |
| `-o`, `--output` | `table` (default), `json`, `yaml`, or `csv` |
| `--read-only` | Block remote writes, local credential changes, and self-update |
| `--dry-run` | For writes: print the requests and send nothing |
| `-y`, `--yes` | Confirm destructive commands and updates without a prompt |
| `--no-input` | Never prompt or open a browser |
| `--raw` | Print Bing's wire JSON without date conversion |
| `-q`, `--quiet` / `-v`, `--verbose` | Fewer notes, or a log line per request, on stderr |
| `--timeout` | HTTP request timeout (default `30s`) |
| `--api-key`, `--access-token` | Credential overrides; prefer `BWT_API_KEY` or `bwt auth login` |

## Account and setup

```bash
bwt auth status                                   # also: login, list, use, logout
bwt doctor --verify                               # local checks plus one GetUserSites call
bwt update --check
bwt completion zsh > "${fpath[1]}/_bwt"
```

## Any Bing method

`bwt api` calls a Bing Webmaster method directly, with the same redaction, error handling, and date
conversion as every other command:

```bash
bwt api methods -o json                                           # every method and its command
bwt api GetUserSites
bwt api GetQueryStats --param siteUrl=https://www.example.com/
bwt api SubmitUrlBatch --data '{"siteUrl":"https://www.example.com/","urlList":["https://www.example.com/a"]}'
```

Known methods use their documented HTTP verb and read/write effect. Writes ask for confirmation, and
`--read-only` refuses them.
